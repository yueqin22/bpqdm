# Host passthrough list for the MotorVF case (see tools/difftest/README.md).
#
# MotorVF.c includes MotorVFInclude.h / MotorInclude.h,
# and that chain reaches the whole motor include tree and, via SystemDefine.h
# -> DSP2803x_Device.h, the chip's peripheral register model.  Same file set
# as the MotorMain case, which walks the identical chain.
#
# MotorVF itself touches no peripheral register directly; the peripheral
# structs are needed only because the real project headers declare them.
#
# Deliberately NOT forwarded (host_patch.json supplies a patched whole copy):
#   DSP2803x_Device.h  -- `extern cregister volatile unsigned int IFR;` and the
#                         EINT/DINT/EALLOW/EDIS `asm(...)` macros are C28x-only.
#                         Replaced by cases/MotorSVC/shim/DSP2803x_Device.h.
#   DSP2803x_PieVect.h -- `typedef interrupt void(*PINT)(void);`
#   MotorInclude.h     -- four `extern interrupt void ..._isr(void);` prototypes
#   SubPrgInclude.h    -- `(long int)` prototypes, illegal once the shim folds
#                         `int` to the target's 16 bits (MSVC C2632)
#   MotorVFInclude.h   -- quoted `#include "MotorInclude.h"` would bypass the
#                         patched gen_dir copy (same-directory rule)
#
# Not forwarded either: DSP2803x_Examples.h / DSP2803x_GlobalPrototypes.h /
# DSP2803x_DefaultISR.h are full of `__interrupt` and `asm()`.  DSP_CLOCK comes
# from SystemDefine.h itself (it `#define`s DSP_CLOCK60 and then DSP_CLOCK).
